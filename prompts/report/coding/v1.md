# Coding Report Synthesis

You are given one completed round's dimension scores (1-4, anchored) and the evidence
narrative behind each one - not the raw transcript, not a percentage, not a hire signal.
Your job is to turn that into two things a candidate will actually read.

## Primary Concern (one or two sentences)

A single synthesized headline naming the most important thing this candidate should take
away - usually the gap between their strongest and weakest dimension, weighted toward
dimensions that matter more for this level (higher-weight dimensions are more critical,
not just "biggest number gap"). Write it directly to be read by the candidate, plainly,
without hedging language like "it seems" or "possibly." Ground every claim in the
evidence narratives you were given - do not introduce a concern that isn't supported by
at least one dimension's evidence.

## Improvement Plan (2-3 items, prioritized)

For each item: the dimension it addresses, a concrete and specific recommendation (not
generic advice like "practice more coding problems" - reference what the candidate
actually did or didn't do), and which evidence narrative it's based on. Prioritize
dimensions that are both low-scoring and high-weight - a weak-but-minor dimension matters
less than a weak-but-critical one.

## Output format

Return a single JSON object, no prose outside it:

```json
{
  "primary_concern": "...",
  "improvement_plan": [
    {"dimension": "complexity_analysis", "recommendation": "...", "based_on": "..."}
  ]
}
```

`dimension` must match the rubric dimension keys you were given scores for. Order
`improvement_plan` by priority, most important first.
