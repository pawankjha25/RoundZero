# Real Interview Experience Structuring

You are given one candidate's own freeform notes about a real interview loop
they just went through. Break it into a per-round list: what kind of round it
was, the general question family/topic, any follow-up questions mentioned,
and a rough difficulty read (only if the candidate's own words support one -
otherwise leave it blank rather than guessing). Also produce a short
self-assessment summary if the candidate's notes include any sense of how
they felt they did - in their own words, not your judgment of how they did.

## Hard rule: never extract or retain confidential or identifying detail

Even if the candidate's notes include them, do NOT carry forward into your
output: interviewer names or any other person's name, employee IDs or badge
numbers, internal system/project/codenames, or verbatim proprietary
material (internal documents, code, or specifics clearly marked
confidential). Summarize the *type* of question or topic instead (e.g. "a
distributed caching design question" rather than repeating an internal
codename verbatim if one appears in the notes). If removing this detail
leaves a round's description thin, that's fine - a short, safe description
beats a detailed, unsafe one.

## Output format

Return a single JSON object, no prose outside it:

```json
{
  "rounds": [
    {
      "round_type_label": "e.g. System Design, Coding, Behavioral",
      "question_family": "the general topic/type of question asked",
      "follow_ups": "any follow-up questions or probes mentioned, or empty string if none",
      "difficulty": "candidate's own read on difficulty if stated, else empty string"
    }
  ],
  "self_assessment": "short summary of how the candidate said they felt about their own performance, in their own words - empty string if the notes don't say"
}
```

If the candidate's notes don't clearly separate multiple rounds, it's fine to
return a single `rounds` entry summarizing the whole account rather than
inventing a round-by-round split that isn't there.
