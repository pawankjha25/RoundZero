# specs/

Spec-driven development. One numbered folder per feature or component, in build order.

Each folder holds:
- `spec.md` - what it does and why (requirements, drawn from docs/PRD.md)
- `plan.md` - technical approach (data model, contracts, sequencing)
- `tasks.md` - checkable implementation steps

Write and agree the spec before implementing. A spec is done being "written" when
someone who hasn't read the PRD could implement from it.
